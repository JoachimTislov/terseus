## 2. Abstraction-level definitions

- **L0 — concrete implementation**: source and tests are the specification. Best when behavior is small, language-specific, and readily reviewed end-to-end.
- **L1 — typed reusable components**: named components expose typed ports and contracts, attach test/build evidence, and compose by version. Generated code is subordinate to these definitions.
- **L2 — recursive declarative system**: compact declarations expand recursively into workflows and code, carrying constraints and provenance. It requires deterministic expansion and a termination proof.

Scoring, 0–4:

- **Semantic fidelity**: how directly the level represents real behavior.
- **Extensibility**: ease of adding capabilities or providers without forks.
- **Change-locality**: containment of ordinary changes.
- **Verification**: strength and traceability of executable checks.
- **Reviewability**: ability to understand consequences in review.
- **Compression**: reduction in authoritative representation without hiding essential semantics.

`0` is unusable, `1` poor, `2` mixed, `3` good, `4` excellent. Scores are reasoned estimates, not measurements.

## 5. Compression versus semantic distance

Compression is beneficial only when repeated structure dominates project-specific meaning.

- In **common-tools**, L2 compresses four functions into declarations but adds an interpreter, schema, diagnostics, and expansion rules. Compression is high; semantic distance is worse.
- In **lite-jnc**, declaring stage order and backend selection removes repeated dispatch while preserving compiler concepts. Declaring parser state transitions could compress code, but debugging generated recovery behavior would become harder.
- In **foodsavr**, L1 compresses repository/provider boilerplate through interfaces, DI, and Freezed while leaving business rules visible. L2 could compact routes, CRUD, and workflows, but provider quirks and model migrations would be split between declaration and handwritten escape hatches.

Thus compression alone never selects L2.

## 6. Recommended level and hybrid boundary

- **common-tools: L0**, with a narrow L1 transport protocol only when a second provider is actually added.
- **lite-jnc: L1**, plus optional L2 for a finite compiler-stage DAG. Lexer, parser recovery, AST/IR semantics, and emitters remain handwritten L0 projections behind typed ports.
- **foodsavr: L1**, retaining Dart models, services, widgets, migrations, and tests as explicit components. Allow schema-driven generation for serialization/DI metadata, but not a recursive application DSL.

Lower levels are safer for destructive FTP traversal, parser error recovery, data migration, UI behavior, authentication, and external-provider interpretation because their operational details need direct review and testing.

## 7. Reusable declaration kernel

**Proposal, language-neutral pseudocode:**

```text
type TypeRef = { name: String, version: SemVer }

type Port<I, O> = {
  name: String, input: TypeRef<I>, output: TypeRef<O>
}

type Contract<I, O> = {
  pre: Predicate<I>,
  post: Predicate<(I, O)>,
  compatibility: SemVerRange
}

type Evidence = {
  kind: Test | Analysis | Schema | ReproducibleBuild,
  artifact: Digest,
  command: String,
  sourceRevision: Digest
}

type Component<I, O> = {
  id: String, version: SemVer,
  input: Port<Unit, I>, output: Port<O, Unit>,
  contract: Contract<I, O>,
  implementation: SourceRef,
  evidence: List<Evidence>
}

type Composition<A, B> =
  Leaf(Component<A, B>) |
  Sequence(Composition<A, X>, Composition<X, B>) |
  Parallel(List<Composition<A, B>>) |
  Choose(Predicate<A>, Composition<A, B>, Composition<A, B>) |
  Ref(ComponentId, SemVerRange)
```

Finite recursion measure:

```text
measure(c) = (remainingRefFuel, unexpandedNodeCount)
```

Every `Ref` expansion must reduce `remainingRefFuel`; every non-reference rewrite must reduce `unexpandedNodeCount`. Cyclic version references are rejected before expansion. Both measures are natural numbers, ordered lexicographically.

Worked lite-jnc example:

```text
Sequence(
  Leaf(ParseJavaa:
    Port<Path, ASTv1>,
    Contract(fileExists, errors <= configuredLimit)),
  Leaf(EmitGo:
    Port<ASTv1, GoSource>,
    Contract(ASTv1-compatible, outputParsesAsGo))
)
```

`ParseJavaa` projects to `parser.New(...).Parse()`. `EmitGo` projects to a typed backend replacing the current placeholder `transpiler.Run`. Evidence would link parser fixtures, Go parser validation, and the exact generator/compiler revision.

## 8. Verification and provenance requirements

Every projection should record:

- declaration digest, generator version, source revision, component versions, and dependency lock digest;
- deterministic input/output digests and generated-file headers;
- port compatibility and contract-validation results;
- evidence tied to the component version, never merely “tests passed” globally;
- a readable expansion trace from declaration node to generated symbol/file;
- rejection of stale evidence after declaration, generator, contract, or dependency changes.

L2 additionally requires cycle detection, the finite measure above, bounded expansion size, deterministic ordering, and golden expansion tests. Generated output must be reviewable without trusting the generator blindly.

## 9. Buildable follow-up

**Proposed next slice:** validate L1 on lite-jnc by introducing a typed backend boundary without building a general DSL.

Slice:

1. Define exported `FrontendResult`/IR and `Backend` interfaces.
2. Adapt parsing behind the frontend port.
3. Adapt ELF and Go targets behind explicit backend implementations.
4. Replace map/default dispatch with validated target lookup.
5. Add table-driven target-selection, unsupported-target, parser-error, and Go-output parseability tests.
6. Emit a small provenance manifest containing target, source digest, backend version, and evidence IDs.

Acceptance criteria:

- unsupported targets return errors rather than falling through to ELF or terminating with `log.Fatalf`;
- each supported target is selected through one typed registry;
- malformed input prevents backend execution;
- generated Go parses with Go’s parser;
- existing supported parsing behavior remains represented by fixtures;
- recursive declarations are not introduced in this slice.

This tests the highest-value L1 seam before deciding whether pipeline-only L2 earns its complexity.
